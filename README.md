## 本版关键决策

- 产品主线：收藏整理 → 排餐 → 核对食材 → 采购 → 跟做 → 家庭反馈。
- 本地原型先验证手动建菜谱、本地图片、日历、核对及清单，不依赖抖音自动解析。
- 共享厨房作为首个联网版本的核心能力，需要身份认证、服务端权限与同步。
- 自动提取视频内容先做独立验证，再接入正式流程；不承诺任意链接均能解析。
- 当前实现为原生微信小程序 JavaScript + 微信云开发；技术文档中的其他栈属于备选设计。

## 运行与检查

1. 克隆后，在微信开发者工具中导入 **`app/`**，不要导入仓库根目录。
2. 配置自己的 AppID：`app/project.config.json`；配置云环境：`app/miniprogram/config.js`。仓库当前保留项目的环境标识（不是密钥），无权限账号需要替换。
3. 在云开发创建 `kitchens`、`invitations`，客户端权限设置为“所有用户不可读写”，部署 `app/cloudfunctions/kitchen` 并安装依赖；AI 请求需要云函数超时至少覆盖请求期限，当前项目配置为60秒。
4. 在应用内填写个人 AI 或 Groq API Key，不放入源码。Groq 直传还需验证上传合法域名和网络可达性。
5. 在仓库根目录执行 `npm --prefix app test` 和 `npm --prefix app run check`。测试只使用内置 Node 模块，不需要真实 API Key。

## 隐私与配置

API Key 默认仅在会话中保存，用户可明确选择在本机记住；不进入菜谱备份或厨房共享。云函数运营方控制执行环境，不能理解为密钥对运营方不可见。运行截图、联调产物、微信开发工具私有配置与环境密钥文件均不提交。开发记录包含历史阶段，阅读时以最新记录为准。
