# 数据模型

状态：逻辑模型草案，不是已执行的数据库迁移。

## 公共约定

ID 使用不可预测的唯一标识。时间存 UTC，日历日期另存本地日期和 IANA 时区。数量用十进制定点值，不能用浮点数做精确扣减。可编辑业务对象包含 version、created_at、updated_at；可恢复删除对象包含 deleted_at。引用关系需要完整性校验和删除策略；关系型实现使用外键，文档数据库由业务层及事务落实。

## 必须满足的约束

- Recipe、MealPlan、ShoppingList 的 owner_user_id 必填；kitchen_id 为空时仅所有者可访问，非空时所有者须为创建者且访问受厨房成员关系控制。
- RecipeStep 的 recipe_id + position 唯一；步骤和食材关联必须属于同一菜谱。
- MealPlanItem 必须二选一：引用菜谱或填写自由文本。引用厨房菜谱时必须属于同一厨房；私人菜谱需先复制到厨房。
- 数量非负；人数为正；时间长度为正；允许未知数量为空，不能把未知当作零。
- 同一日历项可以有多道菜；查询时索引空间、local_date、meal_slot。
- 认领人必须是当前厨房成员；退出后清除未完成认领，已购买历史保留显示身份快照。
- 菜谱软删除后，排餐显示不可用并提示替换；旧采购清单保留生成快照与来源，不静默重算。
- 厨房副本有独立 ID 和媒体权限，source_recipe_id 只用于溯源，不能据此授予原稿访问权。
- 首版定时器属于个人设备使用场景，不跨成员同步响铃。

## 版本与快照

清单生成时保存菜谱版本与食材贡献快照。菜谱更新不覆盖旧清单；重新生成时对比旧快照。跟做会话开始时保留所需步骤快照，避免正在做饭时被他人编辑改变操作。
