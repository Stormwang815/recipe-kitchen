# 页面与交互

状态：建议方案，未制作视觉原型。

## 主导航

建议四个入口：今日、菜谱、日历、厨房。采购清单从今日和日历直达；个人设置位于头像入口。

| 页面 | 主要内容 | 主要动作 |
|---|---|---|
| 今日 | 当前厨房、今日菜单、采购待办、本机计时器 | 开始跟做、核对食材 |
| 菜谱 | 个人/厨房切换、搜索、标签、想做/做过 | 导入、新建、安排日期 |
| 菜谱详情 | 来源、份数、用料、步骤、家庭备注 | 编辑、跟做、分享、加入厨房 |
| 导入草稿 | 提取结果、疑问项、关键帧选择 | 修改、确认保存 |
| 周历 | 日期、餐次、人数、多道菜 | 添加、移动、复制 |
| 食材核对 | 合并需求、已有量、待确认项 | 批量确认、生成清单 |
| 采购清单 | 分类、数量、来源菜谱、认领、已买 | 勾选、补充、应用菜单变化 |
| 跟做 | 当前步骤、图片、用量、计时动作 | 上一步、下一步、启动计时 |
| 厨房 | 成员、邀请、共享动态 | 邀请、退出、管理成员 |

## 交互约束

- 当前空间始终可见，避免把私人菜谱误发布到厨房。
- 分享区分“加入厨房”和“对外分享”。外部分享首版可只发送邀请；公开菜谱分享延后。
- 自动整理结果用“草稿”标识，疑问项放在确认入口附近。
- 做饭模式不弹出非必要营销、协作动态或导入消息。
- 删除、覆盖采购数量等操作提供撤销或确认；普通保存不反复确认。
- 采购认领与购买完成为不同状态，并显示认领人。
- 手机窄屏以列表和每日展开为主，周历不强塞完整菜名。

## 必须设计的异常状态

空菜谱库、链接无法处理、视频超限、图片缺失、无网络、邀请过期、权限失效、同步冲突、通知不可用、数量单位不能合并。每个异常要有可执行下一步，例如手动整理、重试、重新核对。
