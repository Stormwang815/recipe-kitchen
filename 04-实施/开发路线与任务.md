# 开发路线与任务

状态：全部未开始。按交付物推进，不先承诺日程。

## P0 平台选择与风险验证

- [ ] 确定首发用户、设备与平台，记录技术决策。
- [ ] 用 10 条样本验证链接、本地视频、截图与整理路径。
- [ ] 验证目标平台的存储、锁屏计时、后台提醒、分享及邀请能力。
- [ ] 确定媒体是否外发、服务费用上限和存储策略。

完成条件：有可查看的验证记录；自动导入失败时有手动路径。此阶段不要求购买云服务或注册付费产品。

## P1 本地闭环原型

- [ ] 实现手动菜谱、食材、图片步骤、份数和标签。
- [ ] 实现按菜名、食材、作者搜索。
- [ ] 实现跟做模式和可恢复的多个计时器。
- [ ] 实现周历、人数、自由文本餐次与移动排餐。
- [ ] 实现食材核对、单位换算、采购清单与勾选。
- [ ] 实现本地导出、导入及数据清理提示。

完成条件：无自动视频识别也能独立走完整个流程；本地数据重启后可恢复，导出可回读。

## P2 共享厨房联网版

依赖 P1 数据模型稳定。

- [ ] 账号、厨房、邀请、角色与服务端权限。
- [ ] 私人菜谱显式复制到厨房，设置媒体访问权限。
- [ ] 共享排餐、采购认领和已买同步。
- [ ] 版本冲突、软删除、审计记录、成员退出。
- [ ] 验证两个账户与两个设备的真实协作流程。

完成条件：一人排餐、另一人核对买菜、双方查看一致；权限负面测试通过。

## P3 视频与 AI 增强

依赖 P0 可行性结果，可先接本地视频而跳过链接解析。

- [ ] 视频选帧与手动时间点调整。
- [ ] 转写、结构化、证据定位、草稿确认。
- [ ] 失败重试、取消、处理限额与临时文件清理。
- [ ] 用户授权上传与服务费用监控。

完成条件：样本结果可复核，缺失信息不编造，失败不会丢失用户输入。

## 建议的首个开发任务

做一个可在手机浏览器查看的交互原型，展示“个人菜谱 → 排入周历 → 核对食材 → 采购勾选 → 跟做计时”。此为建议，尚未开始编写应用，也未替用户最终选择发布平台。
