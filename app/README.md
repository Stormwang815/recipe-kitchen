## 本地项目位置

导入目录为当前 app 目录，project.config.json 指向 miniprogram/ 和 cloudfunctions/。AppID 已通过开发工具可管理列表确认。

客户端没有 npm 依赖，可直接由开发者工具编译原生 JavaScript。当前实现用 JS，未采用技术方案中的候选 TypeScript；后续可迁移，但先以真实编译验证为准。

## 云环境接通条件

1. 验证当前 AppID 的管理权限并选定关联的云环境。
2. 创建 kitchens 与 invitations 集合。客户端数据库直读直写应拒绝；业务通过 kitchen 云函数鉴权。
3. 在开发环境部署 kitchen，安装 wx-server-sdk 依赖；云函数只接受合法小程序调用者，避免开放匿名 HTTP。
4. 在厨房页输入真实环境 ID，检查连接后测试双账号。
5. 需要文字 AI 时，在服务端配置 DEEPSEEK_API_KEY；DEEPSEEK_MODEL 默认 deepseek-flash，可按账号实际可用模型配置。函数超时应覆盖模型等待；真实配额和费用需用户确认。

本说明不是已经完成配置的记录。云端写操作按开发工具实际确认流程进行，不绕过授权。

## 当前实现边界与后续工作

- 为先验证共享逻辑，厨房业务数据暂存在单个有界文档中，350000 字符应用上限，使用整个厨房版本检测冲突。它比技术总方案中的细分集合更简单，但并发粒度较粗；后续需迁移为按菜谱/清单项分集合。
- 共享文字已编写；共享私有图片尚未接通，代码明确拒绝，防止把本地路径当成云端资源。
- 不支持任意抖音链接自动下载；未实现视频自动语音转写、步骤时间定位及自动截图。
- DeepSeek 云函数只有文字整理适配器；模型输出为待确认草稿，未实测准确性、成本和超时。
- 尚无异步视频任务 Worker、配额/计费监控和恢复调度。
- 首版日历快捷选择仅前 6 道，其他菜谱从详情安排。未实现拖拽排餐、自由文本餐次、复制整周。
- 邀请支持撤销全部旧口令、24 小时/10 次限制；后续补充更细的邀请管理与审计。
- 所有者可转移成员角色；真机、真实事务并发与权限配置仍需验证。
- 备份不包含完整视频，当前图片内嵌上限为 8MB。
- 当前未发布体验版或正式版；没有调用收费 AI。
